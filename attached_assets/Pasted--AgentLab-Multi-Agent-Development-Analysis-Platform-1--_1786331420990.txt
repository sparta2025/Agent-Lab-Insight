# AgentLab — Multi-Agent Development Analysis Platform

## 1. Цель проекта

Создать небольшой клиент-серверный проект **AgentLab** — экспериментальную платформу для работы с системой AI-агентов и простым оркестратором.

Главная идея:

> Пользователь передаёт задачу, а Orchestrator самостоятельно определяет, каких специализированных агентов запустить, собирает их результаты и формирует итоговый ответ.

Проект должен объединять три основных сценария:

1. **Code Detective** — анализ проекта и поиск проблем.
2. **Agent Debate** — несколько агентов независимо анализируют одну проблему, после чего Judge выбирает/синтезирует лучший результат.
3. **AI Task Router** — определение подходящих агентов для конкретной задачи.

Это **MVP / экспериментальный стенд**, а не production enterprise platform.

Главный приоритет:

> Максимально простая архитектура, небольшой объём кода и возможность нормально работать на бесплатном тарифе Replit.

# 5. Основной принцип агентов

Агенты НЕ должны быть отдельными сервисами.

Не создавать:

```text
security-agent-server
bug-agent-server
judge-server
router-server
```

Каждый агент должен быть обычным Python-классом.

Базовый интерфейс:

```python
class Agent:
    name: str

    async def run(self, task):
        ...
```

Пример:

```python
class SecurityAgent(Agent):
    name = "security"

    async def run(self, task):
        ...
```

Все агенты работают внутри одного FastAPI процесса.

---

# 6. Orchestrator

Создать центральный:

```text
Orchestrator
```

Он является главным компонентом backend.

Orchestrator должен:

1. получить задачу;
2. определить тип задачи;
3. выбрать агентов;
4. запустить агентов;
5. собрать результаты;
6. передать результаты Judge;
7. вернуть итоговый результат клиенту.

Упрощённая логика:

```python
async def execute(task):
    agents = router.select(task)

    results = []

    for agent in agents:
        result = await agent.run(task)
        results.append(result)

    return await judge.evaluate(task, results)
```

Не усложнять эту систему.

# 7. AI Task Router

Router определяет, какие агенты нужны.

Пример:

```text
"Find security problems"
        ↓
SecurityAgent
CodeReviewAgent
ArchitectureAgent
        ↓
Judge
```

Другой запрос:

```text
"Why does authentication fail?"
        ↓
BugAgent
SecurityAgent
CodeAgent
        ↓
Judge
```

Router может первоначально использовать простой набор правил.

Не требуется сразу делать сложный AI Router.

Например:

```python
if "security" in task.lower():
    ...
```

Позже архитектура должна позволять заменить его на LLM-based Router.

# 8. Code Detective

Реализовать режим анализа кода.

Пользователь может передать:

* текст ошибки;
* фрагмент кода;
* описание проблемы;
* небольшой набор файлов.

Система должна попытаться найти:

* bugs;
* security problems;
* architectural problems;
* suspicious code;
* dead code;
* потенциальные ошибки.

Каждый агент отвечает только за свою область.

Например:

```text
SecurityAgent
BugHunterAgent
CodeReviewAgent
ArchitectureAgent
```

Не нужно создавать сложный полноценный статический анализатор.

LLM-based анализ допустим.

# 9. Agent Debate

Добавить режим:

```text
DEBATE
```

Несколько агентов независимо рассматривают одну проблему.

Например:

```text
Question:
"Should this project use Redis?"
```

Запускаются:

```text
PerformanceAgent
ArchitectureAgent
SecurityAgent
MinimalistAgent
```

Каждый возвращает:

```json
{
  "agent": "architecture",
  "opinion": "...",
  "pros": [],
  "cons": [],
  "confidence": 0.8
}
```

После этого:

```text
                    Question
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
    Agent A         Agent B         Agent C
        │              │              │
        └──────────────┼──────────────┘
                       ▼
                     Judge
                       │
                       ▼
                    Decision
```

Judge должен сформировать единый итоговый ответ.

---

# 10. Judge

Judge — специальный агент.

Он получает:

```text
original task
+
agent results
```

и возвращает:

```json
{
  "decision": "...",
  "summary": "...",
  "confidence": 0.87,
  "recommendations": []
}
```

Judge не должен повторно анализировать весь проект без необходимости.

Его задача:

> сравнить результаты агентов и сформировать итог.

# 17. LLM abstraction

Не привязывать архитектуру агентов непосредственно к конкретному провайдеру.

Создать простой интерфейс:

```python
class LLMProvider:

    async def generate(
        self,
        system_prompt: str,
        user_prompt: str
    ) -> str:
        ...
```

Агенты должны обращаться к нему:

```python
response = await llm.generate(
    system_prompt=...,
    user_prompt=...
)
```

Это позволит позже подключить:

* OpenAI
* Gemini
* Anthropic
* OpenRouter
* локальную модель

без переписывания агентов.

# 22. Критерии успеха MVP

MVP считается готовым, если:

1. React frontend запускается.
2. Python FastAPI backend запускается.
3. Frontend успешно обращается к FastAPI.
4. Можно отправить задачу.
5. Router выбирает агентов.
6. Минимум 3 агента могут работать.
7. Несколько агентов могут анализировать одну задачу.
8. Judge объединяет результаты.
9. Пользователь видит execution pipeline.
10. Есть режим Detective.
11. Есть режим Debate.
12. Есть режим Auto.
13. API key не попадает во frontend.
14. Backend остаётся полностью Python.
15. Проект не требует PostgreSQL/Redis/Celery для запуска.
16. Проект подходит для запуска на бесплатном Replit.

---

# 23. Правило против усложнения

Если при реализации возникает выбор:

```text
простое решение
        VS
сложная масштабируемая архитектура
```

для MVP всегда выбирать:

> **простое решение.**

Не создавать abstraction только ради abstraction.

Не создавать отдельный сервис, если достаточно класса.

Не создавать базу данных, если достаточно памяти.

Не создавать очередь, если достаточно обычного async вызова.

Не создавать сложный frontend, если достаточно React-компонента.

# 25. Важное требование к Replit Agent

Перед написанием большого количества кода:

1. Проверь существующую структуру проекта.
2. Если проект пустой — создай структуру согласно этому документу.
3. Не заменяй Python backend на TypeScript.
4. Не используй Node.js для backend.
5. Не добавляй ненужные зависимости.
6. Не устанавливай инфраструктурные сервисы.
7. Сначала реализуй минимальный рабочий backend.
8. После этого добавляй агентов.
9. Затем frontend.
10. После каждой фазы проверяй запуск.

Не пытайся реализовать весь проект одним большим изменением.

Строго соблюдать:

**Frontend: React + TypeScript + Vite**
